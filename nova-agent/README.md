# ⚡ Nova — Manus-style Autonomous AI Agent

Nova is a self-hosted autonomous agent CLI and local web UI. It plans tasks,
uses tools, observes results, and writes a final report.

## Quick start

```bash
npm install
npm run build
npm run ui
```

Nova binds its UI to `0.0.0.0` and uses `PORT` (default `3000`). With no model
key, the UI can run in mock mode for local verification.

## Agent tools

Nova includes native tools for shell commands, files, web search, GitHub,
Stripe, Clawdbot/OpenClaw, browser use, and computer use. It also includes a
shared **Composio** connector and shared **Zapier**, **n8n Cloud**, and **Make**
webhook connectors so every Nova agent run can dispatch authorized workflows.

### Composio setup

1. Go to https://app.composio.dev and sign in (or create an account).
2. Open **Settings → API Keys** and click **Create API Key**.
3. Copy the key and add it to the Nova server environment or Freebuff Keys tab:

```text
COMPOSIO_API_KEY=your_key_from_composio
COMPOSIO_USER_ID=nova-user
```

`COMPOSIO_USER_ID` is optional; Nova defaults it to `nova-user`. Keep
`COMPOSIO_API_KEY` server-side and never expose it in browser code or client
bundles. One Composio key covers every app you connect inside Composio (GitHub,
Stripe, Slack, Gmail, ...).

### Automation setup

Each automation provider is configured with a webhook URL generated by a
workflow you own. This is intentionally simpler and safer than adding an
unverified provider SDK:

```text
ZAPIER_WEBHOOK_URL=https://hooks.zapier.com/hooks/catch/...
N8N_WEBHOOK_URL=https://your-instance.n8n.cloud/webhook/...
MAKE_WEBHOOK_URL=https://hook.eu1.make.com/...
```

Optional n8n API-key header support:

```text
N8N_API_KEY=your_n8n_api_key
```

Use the provider's **production** webhook URL, not a test URL, for deployed
Nova runs. Keep each URL server-side because webhook URLs act like bearer
credentials. Nova sends a JSON `POST` payload and returns the provider's status
and response. The model-facing tools are:

- `zapier` with `{ "action": "trigger", "payload": { ... } }`
- `n8n` with `{ "action": "trigger", "payload": { ... } }`
- `make` with `{ "action": "trigger", "payload": { ... } }`

Nova will not trigger a provider when its URL is missing, rejects non-HTTPS
URLs, and reports provider errors without crashing the agent. The agent should
only trigger workflows or scenarios that the user has authorized.

Recommended provider setup:

1. **Zapier** (app.zapier.com → **Create Zap**):
   - Trigger app: **Webhooks by Zapier** → event **Catch Hook**.
   - Click **Continue**, then copy the `https://hooks.zapier.com/hooks/catch/...`
     **Custom Webhook URL** it displays.
   - Add any action step you want (or leave the Zap minimal), then **Publish**
     and make sure the Zap is **ON**.
   - Set `ZAPIER_WEBHOOK_URL` to that URL.
2. **n8n Cloud** (app.n8n.cloud → **Workflows** → **Add workflow**):
   - Add a **Webhook** trigger node. Under **Authentication** you may select
     **Header Auth** and set a header name + value (that value is
     `N8N_API_KEY`).
   - Add your downstream nodes, then **Activate** the workflow (toggle top-right).
   - Copy the **Production URL** from the Webhook node (it contains
     `/webhook/...`), not the `/webhook-test/...` URL. Set `N8N_WEBHOOK_URL`.
3. **Make** (make.com → **Create a new scenario**):
   - Click **+** → **Webhooks** → **Custom webhook** → **Add**.
   - Copy the `https://hook.eu1.make.com/...` URL and set `MAKE_WEBHOOK_URL`.
   - Add any further modules, then toggle the scenario **ON** (the bottom
     left switch) and save. A brand-new webhook must receive one POST to be
     confirmed — Nova's `ping` action does exactly that.

The Composio tool has three actions: `list` to discover connected tools,
`execute` to run a selected tool, and `ping` to test the connection. The
automation tools accept `trigger` and `ping`. Native connectors remain
available as predictable fallbacks. All side-effecting actions require an
explicit user request.

### Hugging Face setup

1. Go to https://huggingface.co/settings/tokens and click **Create new token**.
2. Give it a name (e.g. `nova`), keep the default **read** role (add
   **Inference** / *Make calls to Inference Providers* if prompted), and copy
   the `hf_...` token.
3. Add it to the Nova server environment or Freebuff Keys tab:

```text
HUGGINGFACE_TOKEN=hf_your_token_here
```

One token enables both the Hub (model/dataset search) and the OpenAI-
compatible **Inference API** at `https://router.huggingface.co/v1/chat/completions`.
The model-facing tool is `huggingface` with three actions:

- `ping` — verifies the token live via `GET /api/whoami-v2` (Bearer auth).
- `models` — searches the public Hub (no key required) for models by query,
  e.g. `{ "query": "embedding", "limit": 5 }`.
- `infer` — runs a chat completion through the Inference API, e.g.
  `{ "prompt": "Summarize: ...", "model": "HuggingFaceTB/SmolLM2-1.7B-Instruct", "maxTokens": 512 }`.

`infer` is a free/cheap open-model completion route that works as a fallback
brain or sidekick when no paid provider key is set. Nova will not call the
Inference API without a token, and it never exposes the token to the browser.
Like the other shared connectors, Hugging Face appears in the Connectors view
of the UI, in `GET /api/health`, and in `node dist/index.js --verify-connectors`.

## Connector verification ("is my key actually working?")

After adding any key or webhook URL, run the live check:

```bash
node dist/index.js --verify-connectors
```

This sends a harmless `ping` to each configured provider and prints a report:

```text
✔ github       key present (no live call made)
✔ composio     authenticated as "nova-user" — 42 tools available
✔ zapier       HTTP 200 — {"status":"success",...}
✔ n8n          HTTP 200
✔ make         HTTP 200 — {"status":"success"}
✔ huggingface  authenticated as my-token
```

What each status means:

- **`✔ OK`** — live authentication/webhook round-trip succeeded (Composio
  actually creates a session; Zapier/n8n/Make actually receive the ping).
- **`✖ FAIL`** — the call reached the provider but was rejected: check the
  key/URL, activate the Zap/workflow/scenario, or fix auth (`401`/`403`),
  then re-run.
- **`· not configured`** — no key/URL set yet; nothing to verify.

The same live check is available in the UI at `GET /api/connectors/verify`,
and `GET /api/health` reports which connectors are configured (never the
secret values). The automation tools also expose a model-facing `ping` action.

## Dashboard connectors view + scheduled self-check

The Nova web UI (served by `npm run ui`, default port `3000`) now includes a
**Connectors** view (sidebar → Connectors) that surfaces the verification
results directly:

- One card per connector (GitHub, Stripe, Clawdbot, Composio, Zapier, n8n
  Cloud, Make, Hugging Face) with a live status badge and the same detail text
  the CLI reports.
- **Run verification now** — fires `GET /api/connectors/verify` from the UI
  and refreshes every card in place.
- **Scheduled self-check** — the UI server pings configured connectors
  automatically every `NOVA_CONNECTOR_CHECK_HOURS` hours (default `24`, `0`
  disables) and caches the result. `GET /api/connectors/status` returns the
  last scheduled run, and `/api/health` includes `lastCheckedAt`, `lastOk`,
  and `checkIntervalHours` so the dashboard shows how fresh the check is.
- The sidebar footer chips light up for every configured connector, and the
  dashboard auto-refreshes every 30s while open.

The scheduled check uses the exact same harmless `ping` calls as
`--verify-connectors` — it never triggers real workflows and never exposes
keys or webhook URLs to the browser.

## Daily report email (Nova-generated)

Nova generates a daily report — connector health, task stats from the last
24h, version, and timestamps — and POSTs it to a webhook that emails it to
you. Nova owns the schedule, so the email contains real content from Nova
instead of a bare notification.

**Recommended Zapier setup (free plan supports webhooks):**

1. In Zapier, edit the Zap and replace the **Schedule by Zapier** trigger
   with **Webhooks by Zapier → Catch Hook** (free on the Free plan — no
   upgrade needed). Copy the generated `https://hooks.zapier.com/hooks/catch/...`
   URL and set it as `ZAPIER_WEBHOOK_URL`.
2. In the **Email by Zapier** action, map the **Subject** to the payload's
   `subject` field and the **Body** to the payload's `body` field (the
   payload also carries structured `connectors` and `tasks` objects).
3. Publish and keep the Zap **ON**.

**Nova side:**

```text
NOVA_DAILY_REPORT=1            # master switch (default on)
NOVA_DAILY_REPORT_TIME=09:00   # local time the report fires
NOVA_REPORT_PROVIDER=zapier    # zapier | make | n8n (default: first configured)
```

Send the report on demand (great for testing the email path):

```bash
node dist/index.js --report
# or from the dashboard: Scheduled → “Send report now”
# or via API: POST /api/scheduled/report
```

The dashboard's **Scheduled** view shows whether the job is active, the
delivery target, the next fire time, and the result of the last send. Every
run also appears in `/api/scheduled/status` and `/api/health` (`dailyReport`).

## Credential vault (collect & store API keys)

Nova can collect API keys and webhook URLs during a job and store them in an
**encrypted vault** (AES-256-GCM at rest, stored in `vault/keys.json`, chmod
600, gitignored). The master key comes from `NOVA_VAULT_KEY` when set,
otherwise Nova auto-generates `vault/.master.key` on first use.

### Making the vault survive redeploys (important on Render)

Render builds a fresh container on every deploy, so **anything stored only in
`vault/` on the container disk is wiped on each deploy** — including keys you
add in the dashboard's Vault view. To keep vault keys permanently, mirror the
encrypted vault to a remote Redis. Two backends are supported — set **one** of
them:

**A) Standard Redis connection string (recommended — reuse the Redis you may
already have, e.g. Render's managed Redis `redis://red-...`):**

```text
REDIS_URL=redis://red-xxxx:6379
NOVA_VAULT_KEY=<your own master key, any long string>
```

**B) Upstash REST API (no Redis client needed):**

1. Create a free Redis database at https://console.upstash.com.
2. Copy the **REST URL** and **REST token** from the database's REST API tab.
3. Set these in the Render **nova** service environment (or your `.env`):

```text
NOVA_VAULT_KEY=<your own master key, any long string>
UPSTASH_REDIS_REST_URL=https://us1-xxxx.upstash.io
UPSTASH_REDIS_REST_TOKEN=<rest token>
```

`NOVA_VAULT_KEY` is **required** for the remote copy to be decryptable after a
redeploy (without it the auto-generated master key is wiped with the disk).
Once configured, every vault write is mirrored to the remote Redis immediately
and restored automatically on startup — keys survive redeploys, restarts, and
instance churn. `GET /api/vault` and the startup log show the remote backup
status; `NOVA_REDIS_URL`/`NOVA_VAULT_URL`/`NOVA_VAULT_TOKEN` are accepted
aliases.

Ways to use it:

```bash
node dist/index.js --vault set ZAPIER_WEBHOOK_URL https://hooks.zapier.com/hooks/catch/...
node dist/index.js --vault list
node dist/index.js --vault get ZAPIER_WEBHOOK_URL
node dist/index.js --vault rm ZAPIER_WEBHOOK_URL
```

- The **agent** has a `vault` tool (`list` / `set` / `get` / `delete`), so a
  job can collect a key, store it, and use it — end to end.
- The **dashboard → Vault** view stores and deletes entries; values are masked
  and never sent back to the browser (`GET /api/vault` returns names only;
  writes go through `POST /api/vault`, deletes through `DELETE /api/vault/:name`).
- **Connector wiring:** entries stored under their env-var names
  (`ZAPIER_WEBHOOK_URL`, `N8N_WEBHOOK_URL`, `MAKE_WEBHOOK_URL`,
  `COMPOSIO_API_KEY`, `GITHUB_TOKEN`, `STRIPE_SECRET_KEY`, `HUGGINGFACE_TOKEN`)
  are used automatically when the env var is not set — so you can connect
  Zapier/n8n/Make purely from the vault.

## Jobs (autonomous multi-step tasks)

Nova runs whole jobs from JSON files — a `task` string is executed by the
agent with every tool available (web search, vault, automations, browser…):

```bash
node dist/index.js --job jobs/connect-zapier.example.json
```

The included `jobs/connect-zapier.example.json` reproduces the exact kind of
setup job you'd delegate to Nova: collect the Zapier Catch Hook URL → store it
in the vault → verify the connection → email a confirmation. The same pattern
works for n8n and Make.

**What is Make?** Make (formerly Integromat) is a visual automation platform
like Zapier and n8n — you drag modules into *scenarios* that connect apps
(email, Slack, Google Sheets, …). Nova treats it exactly like the others: you
create a **Webhooks → Custom webhook** module, Nova gets the
`https://hook.eu1.make.com/...` URL, and Nova triggers the scenario by POSTing
JSON to it (`MAKE_WEBHOOK_URL`). Free tier: 1,000 ops/month, 2 active
scenarios. Choose Make over Zapier if you prefer its pricing or builder;
Nova's `make` tool works the same as `zapier` and `n8n`.

## Bounty sweep automation

Nova runs a standing **bounty sweep** (see `prompts/bounty-sweep.md`): it scans
GitHub for open, winnable bounties — 5 dedicated bounty programs plus 23
high-value AI repos — ranks them by (value × likelihood of winning), and writes
a human-review deck to `web/artifacts/bounties/bounty-report-<date>.md`.

**Nova is READ-ONLY against GitHub by design:** it never posts comments, opens
issues/PRs, or submits anything. Every sweep produces drafts for a human to
review and approve first (the UI shows a “HUMAN REVIEW REQUIRED — draft only”
banner on sweep tasks).

- **Manual run:** the UI’s **Run bounty sweep** button or `POST /api/sweep`.
- **Automated run:** Nova self-schedules the sweep via `NOVA_SWEEP_TIMES`
  (comma-separated `HH:MM` in `NOVA_SWEEP_TZ`, default `07:40,19:40`
  America/New_York). Set it to `0` or empty to disable.
- **Status:** `GET /api/sweep/status` (schedule, next run, last run, scope) and
  `GET /api/health` → `bounty`.
- **Full vs limited scan:** with `GITHUB_TOKEN` set (env or vault) Nova runs the
  full 28-repo scan at 5,000 req/hr. Without it, the sweep runs a 10-repo
  limited scan at anonymous rate limits — the UI shows which mode is active.
- **Cron backup:** `cron-jobs/cron-jobs.json` job #10 POSTs to `/api/sweep`
  twice daily as an external trigger/keep-alive.
